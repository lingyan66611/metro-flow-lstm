# 第一步：口径对齐（原始刷卡记录 ↔ HZDT）

这五个脚本只做一件事：把 `archive` 里的原始刷卡记录还原成论文用的 5 min 汇总表，并逐格核对。核对通过后才进入预处理与建模。

## 文件

| 文件 | 作用 |
|---|---|
| `config.py` | 口径与路径的唯一来源，其他脚本只 import 它，不各自写死 |
| `aggregate_archive.py` | 原始记录 → 5 min 长表，按天缓存 |
| `hzdt_reader.py` | 只用标准库读取 HZDT.xlsx（不需要 pandas / openpyxl） |
| `compare_hzdt.py` | 逐格比较，输出汇总与差异清单 |
| `run_align.py` | 串起来：聚合 → 合并 → 对账 |

产物：

- `data/days/2019-01-XX.csv`：单日缓存，80 站 × 209 格，含零值格
- `data/archive_5min.csv`：合并长表，418 000 行
- `data/station_lines.csv`：站点—线路对照（A/B/C）
- `results/align_report.json`：对账汇总
- `results/align_mismatch.csv`：差异清单（本次为空，只有表头）
- `figures/`：后续作图统一放这里

## 冻结口径

| 项 | 取值 | 依据 |
|---|---|---|
| 时间粒度 | 5 min | 立项报告"预测未来 5 分钟客流" |
| 统计时段 | 06:00:00—23:20:00，209 格/日 | HZDT 边界实测 |
| 计数规则 | status=1 进站、status=0 出站，直接计数、不去重 | 与 HZDT 逐格一致 |
| 站点 | 80 个（0—80 中缺 54） | 原始记录实测 |
| 输入/步长 | 12 步 → 1 步 | 技术路线 |
| 划分 | 按时间顺序 70/15/15 | 论文实验设计 |
| 指标 | MAE、RMSE、MAPE、R² | 论文第 5 章 |

## 实测结论（25 天全量）

- 25 天、80 站、209 格/日 = **418 000 格**，与 HZDT **逐格完全一致**，数值差异 0 格，两侧缺格 0 格。
- HZDT 多出 **2 000 格**（80 站 × 25 天）为 `23:25` 末格，其中 67 格非零。核对确认该格只统计时间戳**恰好为 23:25:00** 的刷卡：2019-01-01 全站该格原始计数为 1 进 3 出，与 HZDT 完全相同。这是分桶边界造成的伪格，不是完整的 5 min 窗口。
- 所以 HZDT 的真实口径是：不去重、按 5 min 起始时刻分桶、截止到 23:25:00。
- 单日运营时段外（23:25—次日 05:59）刷卡约 4 500—9 400 条，是夜间工时或设备记录，已单独计数后丢弃。

## 建模前必须做的两处修正

1. **剔除末格**。HZDT 每天 210 行里最后一格是伪值，直接入模会让每天末尾出现一个人为低谷，还会让跨日滑窗学到错误规律。改用 209 格/日后，单站总序列为 5 225 片（25 天 × 209），滑窗 12→1 后为 5 213 个样本，按 70/15/15 约为 3 649 / 782 / 782。
2. **不要对结果去重**。HZDT 未去重，自行去重会与论文表格对不上（抽样单日完全重复 532 条，占比约 0.02%）。是否去重应在论文数据说明里写清楚，不能两套口径混用。

## 论文回填位置

- 数据来源：说明 HZDT 由 archive 原始记录按下述口径聚合，并给出 418 000 格逐格一致的核对结论。
- 预处理：注明 54 号站无记录、末格剔除、时段外记录剔除数量。
- 实验设置：样本数量按上表口径书写，图表横轴统一标为 5 min 起始时刻。
